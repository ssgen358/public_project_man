## 1. 凡例

### 1.1 文書番号体系

文書番号は以下の形式で付番する。

```
{工程コード}-{文書種別コード}-{連番3桁}
例：MNG-PLC-001
```

- 連番は **工程コード × 文書種別コードの組み合わせ** の中で `001` から始まる
- 文書の追加・削除があっても既存の番号は変更しない（欠番は許容する）

> [!NOTE]
> プロジェクト開始時に本台帳をコピーし、「任意」の文書を省略するか否かを意思決定してテーラリング結果として記録する。省略する場合はステータスを「99.対象外」と記載する。

### 1.2 工程コード

| コード | 工程名 | 対応フォルダ |
| :---: | :--- | :--- |
| `MNG` | プロジェクト管理 | `00.管理/` |

### 1.3 文書種別コード

| コード | 文書種別 | 説明・主な例 |
| :---: | :--- | :--- |
| `PLC` | 計画書・方針書 | プロジェクト計画書、テスト計画書 |
| `SPC` | 仕様書・定義書・設計書 | 要件定義書、基本設計書、詳細設計書 |
| `RPT` | 報告書 | フェーズ完了報告書、進捗報告書 |
| `EVD` | エビデンス・試験成績・記録 | テスト結果、品質記録、作業ログ |
| `REG` | 台帳・一覧 | 文書管理台帳、課題管理台帳 |
| `MNL` | 手順書・マニュアル | 運用手順書、リリース手順書 |
| `CHK` | チェックリスト | レビューチェックリスト、リリース確認 |
| `TMP` | テンプレート | 議事録テンプレート、報告書フォーマット |

### 1.4 テーラリング区分

| 区分 | 意味 |
| :---: | :--- |
| ◎必須 | プロジェクト規模・種別によらず作成が必要 |
| 〇推奨 | 一般的には作成が望ましい。省略する場合は理由を明示する |
| △任意 | プロジェクトの性質・規模に応じて判断する |

### 1.5 ステータス区分

| ステータス | 意味 |
| :---: | :--- |
| 00.未作成 | 作成着手前 |
| 10.作成中 | 作成・編集中 |
| 20.レビュー中 | レビュー実施中 |
| 30.承認済 | 承認完了 |
| 90.完了 | 最終版確定（変更管理対象） |
| 99.対象外 | テーラリングにより本プロジェクトでは作成しないと決定 |

### 1.6 各項目の説明

| 項目 | 説明 |
| :--- | :--- |
| 文書番号 | 体系に基づく一意の識別子 |
| 文書名 | 正式名称 |
| 保管先 | リポジトリ内の相対パス、またはシステム名（Redmine 等） |
| 形式 | ファイル拡張子（.md / .xlsx / .pptx 等）。複数形式の場合は主となるものを記載 |
| テーラリング | ◎必須 / 〇推奨 / △任意 |
| 納品 | 顧客への納品対象か否か（〇必要 / ー対象外） |
| 承認 | 承認要否（〇要 / ー不要） |
| 承認者 | 承認権限を持つロール（PM / PL / 顧客 等） |
| ステータス | 現在の作成状況 |
| 作成者 | 担当ロール |
| 作成予定 | 計画値（yyyy/mm/dd） |
| 作成日 | 実績（yyyy/mm/dd） |
| 更新日 | 最終更新の実績（yyyy/mm/dd） |
| 備考 | 補足・依存関係・参照先等 |

> [!TIP]
> 「ステータス」「作成者」「作成予定」「作成日」「更新日」はプロジェクト固有の情報。プロジェクト開始時に本台帳をコピーして各プロジェクト用に編集する。
